*[Read in English](/blog/events-that-scale)*

In einer App auf der Heisenware-Plattform registrierte ein Zähler seinen
Event-Handler einmal pro Minute neu. Nichts dazwischen wusste, dass es
derselbe Zuhörer war. Nach 19 Stunden hielt die Instanz 1.100 Kopien
desselben Handlers, und jeder Impuls des Zählers ging 1.100-mal hinaus.

VRPC 3.15 beendet das endgültig. Es bringt Protokoll 4 und damit eine
einfache Regel: **Eine Event-Funktion läuft einmal, egal wie viele
zuhören.**

## Was VRPC ist

VRPC macht die Klassen eines Programms für andere Programme aufrufbar, als
wären sie lokal. Sie registrieren eine Klasse bei einem Agenten; jeder
Client – ein Backend-Dienst, ein Browser, ein Gerät – erzeugt Instanzen
davon, ruft ihre Funktionen auf und hört auf ihre Events. Agenten und
Clients bauen nur ausgehende Verbindungen zu einem MQTT-Broker auf. So ist
auch Code hinter einer Firewall erreichbar, und es gibt keine API-Schicht zu
schreiben: Die Klasse ist der Vertrag.

```javascript
// auf dem Raspberry Pi in der Küche
const { VrpcAdapter, VrpcAgent } = require('vrpc')

class Sensor { /* read(), onReading(handler) */ }

VrpcAdapter.register(Sensor)
new VrpcAgent({ domain: 'home', agent: 'pi-kitchen' }).serve()
```

```javascript
// überall sonst: in einem Backend, in einem Browser
const { VrpcClient } = require('vrpc')

const client = new VrpcClient({ domain: 'home' })
await client.connect()
const sensor = await client.getInstance('kitchen')
console.log(await sensor.read())
await sensor.onReading(celsius => chart.add(celsius))
```

## Eine Registrierung, viele Subscriptions

Vor 3.15 erreichte jeder abonnierende Aufruf die Event-Funktion der Klasse
aufs Neue. Zehn Browser an einem Sensor bedeuteten zehn Zuhörer darauf, und
ein Client, der nach einem Verbindungsaussetzer erneut abonnierte, fügte
einen weiteren hinzu. Protokoll 4 trennt zwei Dinge:

- Eine **Registrierung** ist der eine Aufruf einer Event-Funktion, für eine
  Instanz, eine Funktion und deren Argumente. Der Agent macht ihn einmal.
- Eine **Subscription** ist der Wunsch eines Zuhörers, diese Events zu
  erhalten. Subscriptions sind Mengen: Wer eine Subscription erneut
  erklärt, ändert nichts.

Der Agent reicht jedes Event einer Registrierung an alle ihre Subscriptions
weiter und gibt die Registrierung frei, sobald die letzte Subscription geht.
Zehn Browser an einem Sensor sind ein Zuhörer am Emitter, nicht zehn – und
der Zähler von oben hält genau einen.

## Sagen Sie VRPC, wie es rückgängig geht

Eine Event-Funktion gibt ein Registrierungsobjekt zurück. Es sagt, wie die
Registrierung freigegeben wird, und optional, wie ein Neuer begrüßt wird:

```javascript
onReading (handler) {
  this._emitter.on('reading', handler)
  return {
    [Symbol.dispose]: () => this._emitter.off('reading', handler),
    greet: greeting => greeting(this._reading)
  }
}
```

`[Symbol.dispose]` läuft, wenn der letzte Abonnent geht. `greet` läuft für
jeden neuen Abonnenten, den ersten eingeschlossen. So startet jeder mit dem
aktuellen Messwert, statt auf die nächste Änderung zu warten – egal, wie spät
er dazukommt.

## Enden werden mitgeteilt, Verluste heilen

Eine Registrierung kann enden: Ihre Instanz wird gelöscht, oder die Klasse
beendet sie. Jeder Abonnent erfährt davon, und der Client meldet `ended`,
statt den Handler weiter aufzurufen. Geht ein Agent offline, behält der
Client seine Subscriptions dort und erklärt sie erneut, sobald der Agent
zurück ist – er meldet `lost`, dann `healed`, und niemand muss etwas neu
aufbauen.

## Weniger Bytes, weniger Anfragen, weniger Überraschungen

- **Antworten tragen nur, was ein Aufruf ergab.** Sie wiederholen die
  Argumente nicht mehr, wodurch ein großes Argument zweimal durchs Netz
  ging.
- **`callAll` wählt Instanzen aus.** `instances: 'line-3*'` ruft nur diese
  auf, mit einer Anfrage pro Agent, egal wie viele Instanzen er hält, und
  `agent: 'edge-*'` fragt alle passenden Agenten auf einmal.
- **Aufrufbar ist nur, was eine Klasse veröffentlicht.** `emit` und private
  Hilfsfunktionen waren mit einer selbst gebauten Anfrage erreichbar; jetzt
  nicht mehr, und `@private` im JSDoc hält eine Funktion ebenfalls drinnen.
- **Jede Anfrage, die einen Agenten erreicht, wird beantwortet**, und Fehler
  reisen als `{ message, cause }`.

## Aufgeschrieben

Protokoll 4 ist Regel für Regel in der
[Protokollspezifikation](/docs/spec/protocol) festgelegt: nummerierte Regeln
und Tests, die die Regel nennen, die sie prüfen. Sie gilt für jede
VRPC-Implementierung. Die Portierungen für C++, Python und Arduino sprechen
heute Protokoll 3, und das funktioniert weiter: Ein Agent ab 3.15 bedient
ältere Clients, und ein Client ab 3.15 spricht mit älteren Agenten.
